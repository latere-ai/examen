# API

## Overview

The contract a client codes against: a command-line client, a console,
a CI job that holds a release to a bar, a training loop that reads an
export. Through it a client applies versioned objects by name, creates,
changes, follows, cancels and deletes experiments, reads cells, trials,
measurements and comparisons, re-grades trials, pins baselines,
evaluates bars, keeps the taxonomies of open-vocabulary metrics,
shares, exports datasets, works an annotation queue, imports trials
Examen did not start, leases and submits the trials an external harness
runs, reads reports, publishes and withdraws reports, benchmarks and
datasets, and submits results to a benchmark; a reader who does not
sign in reads what was published through the public routes. The contract
is one OpenAPI 3.1 document in the public package `api`, served by the
binary and held to the handlers by a test. Beside the routes, this spec
fixes the outbound contract with an installation's event sink; the
minter and the key endpoint are spec 004's.

The first consumer is a person comparing agents in a console. The read
side is shaped for it: an experiment's candidate × task grid, paged by
task, and a comparison's results, paged by row, come back already
computed, with their summaries, deltas, intervals, corrected values,
denominators, reasons and confounds, and the progress stream says when
to read them again, so a console renders them as they arrive and
computes no statistic of its own.

Every object shape is spec 002's, with the fields spec 002 names. This
spec fixes the routes, the conventions every route shares, the computed
read views, the progress stream, idempotency, and the errors. Each route
names the action it asks the authorizer; what that action carries and
how its answer is held is spec 004's.

## Design

### Conventions

All routes sit under a base path, `/v1` by default, set by
`EXAMEN_BASE_PATH` (spec 011), so a deployment can mount the surface
under a prefix of its own. A route written `/suites` here is served at
`{base}/suites`. Every route below the base path needs a bearer token
(spec 004), except `GET /openapi.yaml`, which serves this contract, and
the public routes under `/public/` (Public reads, below). The
probes `GET /livez`, `GET /readyz` and `GET /version` are those of
`latere.ai/x/pkg/health`, sit outside the base path on the same
listener, and need no token (spec 011). `GET {base}/version` answers
the same body under the base path, with no token, so the build that
serves a deployment is readable through the one prefix its ingress
forwards.

Bodies are JSON in UTF-8. A request with a member the contract does not
describe is `400 unknown_field`. A body longer than `MAX_REQUEST_BYTES`
is `413 request_too_large`, refused before it is read whole. A subject
that sends more than `API_REQUESTS_PER_MINUTE` requests to one replica
within a minute is `429 rate_limited`, through `latere.ai/x/pkg/ratelimit`
(spec 012). Every `429` carries `Retry-After` in whole seconds: for a
rate limit, until the window admits a request again; for
`too_many_streams`, `STREAM_POLL_INTERVAL` rounded up, since a stream
may close at any moment. Times are RFC 3339 in UTC. A duration is a string in Go's
notation, such as `45m` or `2h30m`. Identifiers and digests are spec
002's. A `metadata` member holds at most `METADATA_MAX_PAIRS` pairs,
and a key beginning `examen.` is `400 invalid_field`, since that prefix
is reserved for the labels Examen writes (spec 002).

**The owner context.** Every object belongs to an owner (spec 002). A
request acts in one owner's context: the owner the `owner` query
parameter names, when the request names one; otherwise the owner the
authorizer's allow names in its `owner` limit (spec 004); otherwise the
caller's subject. A name is resolved among the context owner's objects.
A route that resolves names before its own question, as `POST
/experiments` resolves its suite and candidates so its question can
carry them, first asks the list question of its kind with no `owner`,
and resolves in the owner that allow's `owner` limit names; a deny or
an allow naming none leaves the caller's subject.
A rendered subject in a query parameter or a path segment is
percent-encoded as one segment, so `https://issuer.example|9ab3` is
written `https%3A%2F%2Fissuer.example%7C9ab3`.

**Lists.** A list pages by a cursor. `limit` is `DEFAULT_PAGE_SIZE`
when absent and at most `MAX_PAGE_SIZE`; a larger one is `400
invalid_field`. Items are newest first by id, unless the route says
otherwise. The answer is `{"items": [...], "next_cursor": "..."}`, and
`next_cursor` is absent on the last page. A client treats the cursor as
opaque; a cursor this list did not issue is `400 invalid_cursor`. A list
holds only what the authorizer's filter admits (spec 004), narrowed
further by `owner` when the request names one. The envelope and the
error shape are those of `latere.ai/x/pkg/httpjson`. A cursor is the
name of the list that issued it and the key its next page resumes
after, an id or, for the grid and a comparison's rows, a place in the
suite's order, joined by a colon and encoded in unpadded base64url, so
a cursor of one list is refused by another. It is not
`latere.ai/x/pkg/pagination`'s cursor, an integer, since Examen's ids
are strings. An experiment's event log pages by sequence instead, with
`after` (The progress stream, below).

**Names.** A metric's name follows spec 002's rule. A name of any other
kind is 1 to 63 characters of `[a-z0-9._-]`, starting with a letter or
a digit. A name that has the form of an identifier of its kind (its
prefix, an underscore and a ULID) is `400 invalid_field` at apply, so a
path segment is never both.

### References

A versioned object (metric, grader, task, suite, candidate, bar) is
named in a path by a `{ref}` of one of four forms:

| Form | Example | Reads |
|---|---|---|
| a name | `release` | the name's current version, in the context owner |
| `name@digest` | `release@sha256:9f2c…` | that version; `404` when the digest is not a version of that name |
| a digest | `sha256:9f2c…` | the version with that digest in the context owner, else one a suite shared with the context owner pins (spec 004), else, on a route that reads an experiment run through a published benchmark, one that benchmark's suite version pins (spec 013) |
| an id | `sui_01jb…` | that version, whoever owns it, subject to the authorizer |

A reference inside a request body always pins a version: a digest, or
`name@digest`. A built-in metric is named by its reserved digest
`builtin:<name>` (spec 002), which pins it. A reference by name alone, a model alias, an image by
tag, a workspace by branch and an agent without its version digest are
`422 unpinned_reference`, with `details.field` naming the member (spec
002). The one exception is a bar's `suite`, which names a suite by
owner and name (spec 002). A digest resolves first among the context
owner's versions, then among the versions a suite or baseline shared
with the context owner pins, then, for an experiment's `suite` with
`benchmark`, the suite version that published benchmark pins (spec
013). One that resolves to nothing the caller
may use, here or at the core that holds it, is `422
reference_not_found` naming the member; another owner's object the
authorizer does not let the caller use answers the same, so a reference
cannot probe for what exists.

A baseline is named in a body by its record's id, as spec 002 writes
it.

### Versioned objects

Five kinds share one shape: `metrics`, `graders`, `tasks`, `suites` and
`candidates`. `{kind}` below is one of them, and `<kind>` in an action
is its singular.

| Method and path | Purpose | Answers | Action asked |
|---|---|---|---|
| `PUT /{kind}/{name}` | apply a version; `owner` | 201, 200, 400, 403, 412, 413, 422 | `<kind>.apply` |
| `GET /{kind}/{ref}` | one version; `owner` | 200, 404 | `<kind>.read` |
| `GET /{kind}/{name}/versions` | every version of one name, newest first; `owner`, `limit`, `cursor` | 200, 404 | `<kind>.read` |
| `GET /{kind}` | the current version of each name; the filters below, `versions`, `owner`, `limit`, `cursor` | 200, 400, 403 | `<kind>.list` |
| `GET /graders/{ref}/calibration` | a judge version's agreement with people, per metric it produces (spec 006); `metric`, `experiment`, `owner` | 200, 400, 404 | `grader.read` |

**Apply.** The body is the kind's fields from spec 002, such as a
metric's `type`, `range`, `labels`, `direction`, `aggregate`, `unit` and
`description`. `name` may be left out; when present it equals the path's
name, or the request is `400 invalid_field`. Examen validates every
field and every limit of spec 002, which is `422 limit_exceeded` with
`details.constant` naming the constant; checks that every reference is
pinned in form (a digest, a full commit id, an image digest), without
asking another core: an apply has no experiment yet, and an owner token
is minted for an experiment's work (spec 004). That every pin exists is
checked when an experiment that uses it is created. Examen then
computes the digest over the canonical JSON of the kind's
fields, `name` included, and none of `id`, `owner` and `created_at`.
At an experiment's create, as the owner with the purpose `resolve`
(spec 004), Examen resolves every pin the experiment uses and checks
against Cella's admission each task's `environment` image, each
`program` candidate's image and each check grader's `image`: a pin that
does not exist is `422 unresolved_reference` and an image Cella would
refuse is `422 image_not_admitted`, each with `details.field` naming the
task, candidate or grader and the field, so an experiment that cannot
run is refused before any trial starts. On an apply:

- a digest that is not yet a version of the name is stored as a new
  version and becomes the name's current version: `201`;
- a digest that already is a version of the name stores nothing new and
  makes that version current again: `200`.

So a repeated apply creates nothing, and applying earlier content rolls
the name back to its earlier version without making another. The answer
is the version: `{id, owner, name, digest, current, created_at}` beside
the kind's fields, with `ETag: "<digest>"` and `Location:
{base}/{kind}/{name}@{digest}`. An apply that carries `If-Match:
"<digest>"` applies only while that digest is the name's current
version, and `If-None-Match: *` only while the name has no version;
otherwise the answer is `412 precondition_failed`. Two applies to one
name without either header both land, and the one committed last is
current.

Each version has its own id, and `name@digest` also addresses it. A
version is never changed and never deleted through this API, since
experiments pin it; retention is spec 007's. A task's name is unique
per owner, and a suite version that pins two tasks of one name is `422
invalid_field` on `tasks` (spec 002). A suite version that gives one
task two producers of one metric other than annotation graders is `422
invalid_field` on `graders`, naming the metric and both graders (spec
002). A `program` candidate whose `credentials` name an audience
Examen acts through, one of the configured core audiences
(`EXAMEN_TOPOS_AUDIENCE`, `EXAMEN_CELLA_AUDIENCE`,
`EXAMEN_LUX_AUDIENCE`, `EXAMEN_ARCA_AUDIENCE`, `EXAMEN_ORIGO_AUDIENCE`)
or an entry of `EXAMEN_OIDC_AUDIENCE`, is `422
credential_audience_reserved`, with `details.field` naming the
credential: a program under test is never handed a token that would let
it act as the owner toward the services that run and grade it (spec
004).

**List filters.** Each filter is a query parameter, and several narrow
together.

| Kind | Filters |
|---|---|
| metrics | `name`, `type` |
| graders | `name`, `grader_kind`, `produces` (a metric digest) |
| tasks | `name`, `suite` (a suite digest: the tasks that version pins), one `metadata.<key>=<value>` |
| suites | `name` |
| candidates | `name`, `candidate_kind`, `agent` (an agent's name, for its candidates at any version, or one version, `sha256:…` or `name@sha256:…`, for the candidates of that version however they name it), `model`, one `metadata.<key>=<value>` |

`versions=all` lists every version of every name, newest first, in
place of the current version of each name.

**Calibration** answers, for the judge version `{ref}` and each metric
it produces, or the one `metric` names: `{metric, pairs, alpha,
interval, people_alpha, calibrated}`, over the context owner's trials,
or one experiment's when `experiment` names it. Each figure is the one
spec 006 computes and stores. `{ref}` may also be `builtin:decline`; a
grader that is not a judge is `400 invalid_field`.

### Bars, baselines and shares

Bars and baselines are named per owner and suite (spec 002), so they sit
under a suite. `{suite}` is a suite's name, of the owner the
`suite_owner` query parameter names, the context owner when it is
absent. The bar or baseline itself belongs to the context owner, and
a route that names another owner's suite asks `suite.use` of it, which
a share never allows (spec 004): an owner a suite is shared with reads
it and pins no baseline and applies no bar on it. A bar or baseline
names its suite by owner and name and covers every version of it.

| Method and path | Purpose | Answers | Action asked |
|---|---|---|---|
| `PUT /suites/{suite}/bars/{name}` | apply a bar version | 201, 200, 400, 403, 412, 422 | `bar.apply`; `suite.use` for another owner's suite |
| `GET /suites/{suite}/bars/{ref}` | one bar version | 200, 404 | `bar.read` |
| `GET /suites/{suite}/bars/{name}/versions` | every version of one bar | 200, 404 | `bar.read` |
| `GET /suites/{suite}/bars` | the current version of each bar of the suite | 200, 403 | `bar.list` |
| `GET /bars/{id}` | one bar version by id | 200, 404 | `bar.read` |
| `POST /suites/{suite}/bars/{ref}/evaluate` | evaluate a bar version on a comparison | 201, 200, 400, 404, 409, 422 | `bar.evaluate`; `experiment.read` of the comparison's experiment |
| `GET /suites/{suite}/bars/{name}/evaluations` | evaluations of every version of one bar, newest first | 200, 404 | `bar.read` |
| `GET /evaluations/{id}` | one bar evaluation | 200, 404 | `bar.read` |
| `PUT /suites/{suite}/baselines/{name}` | pin a baseline | 201, 200, 400, 403, 409, 412, 422 | `baseline.pin`; `experiment.read` of the experiment named; `suite.use` for another owner's suite |
| `GET /suites/{suite}/baselines/{name}` | the name's current record | 200, 404 | `baseline.read` |
| `GET /suites/{suite}/baselines/{name}/history` | every record of the name, newest first | 200, 404 | `baseline.read` |
| `GET /suites/{suite}/baselines` | the current record of each baseline of the suite | 200, 403 | `baseline.list` |
| `GET /baselines/{id}` | one record | 200, 404 | `baseline.read` |
| `PUT /suites/{suite}/shares/{grantee}` | share the suite with an owner | 201, 200, 400, 403, 404 | `suite.share` |
| `DELETE /suites/{suite}/shares/{grantee}` | stop sharing it | 204, 403, 404 | `suite.share` |
| `GET /suites/{suite}/shares` | the suite's shares | 200, 403, 404 | `suite.share` |
| `PUT /suites/{suite}/baselines/{name}/shares/{grantee}` | share a baseline with an owner | 201, 200, 400, 403, 404 | `baseline.share` |
| `DELETE /suites/{suite}/baselines/{name}/shares/{grantee}` | stop sharing it | 204, 403, 404 | `baseline.share` |
| `GET /suites/{suite}/baselines/{name}/shares` | the baseline's shares | 200, 403, 404 | `baseline.share` |
| `GET /shares` | the shares naming the context owner as grantee; `object` (`suite`, `baseline`, `experiment` or `publication`), `suite` | 200, 403 | `share.list` |

**A bar** is applied as any versioned object. Its body's `suite` is
`{owner, name}` and must name `{suite}` of the suite owner the request
names, or the request is `422 suite_mismatch`. A rule's metric must be
in the suite's current version (spec 009).

**Evaluating a bar** takes one of two bodies: `{"comparison":
"cmp_…"}`, or `{"experiment": "exp_…", "candidate": "sha256:…"}`,
which names the candidate's comparison against the experiment's
`reference`; either may carry `metadata`. The answer is a bar evaluation
(spec 002), here with its `inputs` left out:

```json
{ "id": "bev_01jb…", "owner": "https://issuer.example|9ab3",
  "bar": "sha256:c1d2…", "bar_name": "release",
  "experiment": "exp_01jb…", "candidate": "sha256:41ab…", "comparison": "cmp_01jb…",
  "reference": { "baseline": "bas_01jb…" },
  "state": "complete", "result": "failed",
  "rules": [ { "index": 0, "metric": "sha256:77aa…", "metric_name": "tests_pass",
               "kind": "no_regression", "scope": "all", "result": "failed",
               "reasons": [ { "reason": "regressed",
                              "results": [ { "metric": "sha256:77aa…", "level": "suite" } ] } ] } ],
  "single_variable": true, "confounds": [],
  "metadata": { "commit": "9f2c1e7" },
  "created_by": "https://issuer.example|9ab3",
  "created_at": "2026-10-17T09:30:00Z", "completed_at": "2026-10-17T09:30:00Z",
  "links": { "evaluation": "https://examen.example/v1/evaluations/bev_01jb…",
             "comparison": "https://examen.example/v1/comparisons/cmp_01jb…",
             "console": "https://examen.example/comparisons/cmp_01jb…" } }
```

The comparison, or the experiment that holds it, is asked
`experiment.read` before anything else is checked; a deny is `422
reference_not_found` on the member that names it, so an evaluation
cannot confirm that another owner's comparison exists. An experiment
that is not `complete` is `409 experiment_not_complete`, a canceled one
`409 experiment_canceled`; one that ran no version of the bar's suite is
`422 suite_mismatch`; an experiment body whose candidate is the
experiment's reference candidate, which nothing is compared with, is
`422 no_reference`. The comparison read is the one named, or else the
candidate's newest final comparison against the experiment's
`reference` whose inputs are current; when there is none, Examen
computes one (spec 008) and the evaluation answers in state `pending`,
to be read again with `GET /evaluations/{id}`. A new
evaluation answers `201`, a failing bar included, which is never an
HTTP error. When this bar version has already been evaluated on this
comparison with the same `metadata`, the answer is `200` with that
evaluation, so a retried release check reads one result. `links` are
absolute, built on `EXAMEN_PUBLIC_URL` (spec 011), and absent when it is
unset. What a rule reads and when it passes are spec 009's.

A CI job that holds a release to a bar creates an experiment, follows
its stream until a `comparison` event with `final` true names its
candidate, evaluates the bar, and fails when `result` is `failed`
(spec 009).

**Pinning a baseline** takes `{"experiment": "exp_…", "candidate":
"sha256:…"}`. The experiment is first asked `experiment.read`, and a
deny is `422 reference_not_found` on `experiment`, before any state is
checked, so a pin cannot confirm that another owner's experiment exists.
The experiment must be `complete`, or the request is `409
experiment_not_complete`; it must have run a version of `{suite}`, or
`422 suite_mismatch`; and the candidate must be one of its candidates,
or `422 not_in_experiment`. When the name has no record, or its current
record names another experiment or candidate, a new record is stored,
with `previous` naming the current one, and becomes current: `201`.
When the current record names the same experiment and candidate, the
answer is `200` with it and nothing is stored. Every earlier record
stays readable in the history (spec 002). A record's `ETag` is its id:
`If-Match: "<baseline id>"` pins only while that record is current, and
`If-None-Match: *` only while the name has none; otherwise `412
precondition_failed`.

**A share** is spec 002's: `{id, owner, object, suite, baseline,
experiment, publication, grantee, created_by, created_at}`, with the
members its `object` does not use absent. `{grantee}` is the rendered
subject or organization the share names, percent-encoded. A `PUT` of a
share that exists answers `200` with it. A `DELETE` of one that does
not is `404 share_not_found`. The share routes of an experiment and of
a publication are in their sections below. What a share lets the
grantee do, beside a link and a listing, is spec 013's.

### Taxonomies

An open-vocabulary metric is read through its suite's taxonomy (spec
006), a lineage of records under the suite, as a baseline's is.
`{suite}` is as above, and `{metric}` is the name or digest of an
open-vocabulary metric some version of the suite lists; any other is
`404 taxonomy_not_found`. A taxonomy belongs to the suite's owner.

| Method and path | Purpose | Answers | Action asked |
|---|---|---|---|
| `PUT /suites/{suite}/taxonomies/{metric}` | append a taxonomy version: `{canonical, map}` | 201, 200, 400, 403, 404, 412, 422 | `taxonomy.apply` |
| `GET /suites/{suite}/taxonomies/{metric}` | the current record | 200, 404 | `taxonomy.read` |
| `GET /suites/{suite}/taxonomies/{metric}/history` | every record, newest first | 200, 404 | `taxonomy.read` |
| `GET /suites/{suite}/taxonomies/{metric}/unmapped` | the raw labels of the suite owner's trials that the current record does not map, each with its count, most frequent first | 200, 404 | `taxonomy.read` |
| `GET /taxonomies/{id}` | one record | 200, 404 | `taxonomy.read` |

**Appending** stores the body as the lineage's next record with
`source` `{owner}`, and answers `201` with it; a body whose `canonical`
and `map` equal the current record's stores nothing and answers `200`
with it. A canonical label or a raw label longer than
`LABEL_MAX_BYTES`, a map value that is not one of `canonical`, and a
body that leaves out a raw label the current record maps are `400
invalid_field`; more than `MAX_LABELS_OPEN_VOCABULARY` canonical labels or
`MAX_TAXONOMY_RAW_LABELS` raw labels is `422 limit_exceeded`. A
record's `ETag` is its id: `If-Match: "<taxonomy id>"` appends only
while that record is current, and `If-None-Match: *` only while the
lineage has none; otherwise `412 precondition_failed`. A record a
canonicalizer proposes is appended by Examen, never through this route
(spec 006).

| `GET /comparisons/{id}` | one comparison with its suite-level results, computed | 200, 404 | `experiment.read` |
| `GET /comparisons/{id}/rows` | its task-level results, computed; `metric`, `task`, `verdict`, `limit`, `cursor` | 200, 400, 404 | `experiment.read` |
| `PUT /experiments/{id}/shares/{grantee}` | share the experiment, its grid and its comparisons with an owner | 201, 200, 400, 403, 404 | `experiment.share` |
| `DELETE /experiments/{id}/shares/{grantee}` | stop sharing it | 204, 403, 404 | `experiment.share` |
| `GET /experiments/{id}/shares` | the experiment's shares | 200, 403, 404 | `experiment.share` |

A cell, a trial, a measurement and a comparison are read under the
experiment they belong to: their routes ask `experiment.read` of it, and
a deny answers the `404` of the object asked for. `GET /comparisons`
lists the comparisons of the experiments `experiment.list` admits.

```json
POST /experiments
{ "suite": "release@sha256:9f2c…",
  "candidates": ["sha256:41ab…", "sha256:77d0…"],
  "trials": 20,
  "budget": { "name": "release-eval" },

A level of `candidate` is a candidate reference, a digest or `name@digest`, and one of `task` a task's name or digest. Every form takes an optional `metric`, a metric of the suite by name, digest or `name@digest`, answered by digest. A member missing is `400 missing_field`; members of two forms, a candidate compared with itself, one task twice, a `variable` outside spec 008's table or `task` on a pair of candidates, a pair named twice in either orientation, a general declaration whose `levels` are not two different levels, or whose level or `where` value is empty, whose `variable` is no cell variable or appears in `where` or `by`, whose `where` or `by` names a variable no cell carries, whose `by` names a variable twice or one `where` holds, whose selected cells do not all carry every variable of `by`, whose stratum holds two cells of one side or two cells that also differ in a variable it neither holds nor names, that pairs no stratum, whose strata take one name twice, any comparison declared twice in one form or across forms, such as a pair of candidates and the general form of the same pair, and a `metric` the suite does not list at level `trial` or `cell`, are `400 invalid_field`; a candidate or a task the experiment does not hold, a task a level or a `where` names that the suite does not pin, and a level or a `where` that selects no cell, are `422 not_in_experiment`; a candidate level that is no reference is `422 unpinned_reference`; more than the limit is `422 limit_exceeded`. | `metadata` | optional; spec 002's |
| `sign_in` | optional; an opaque value the client's installation gave it for this create, 1 to `SIGN_IN_MAX_BYTES` bytes of visible ASCII, otherwise `400 invalid_field`. Before anything is stored, Examen checks that tasks × candidates is at
most `MAX_CELLS_PER_EXPERIMENT`; resolves every field of every cell's
provenance tuple as the owner (spec 004), refusing one that is not
pinned (spec 002); refuses a task without an `instruction` when a
candidate is of kind `topos`, `422 instruction_required` with
`details.field` naming the task; with the `lux` key source, after v0.1, reads a
named budget at Lux as the owner, which is `422 budget_refused` when it
does not exist, is not `hard`, or the owner may not draw on it (spec
005), or for a spending cap no authorizer's `budget` limit answered, creates the
Budget as the owner (spec 004); with the `endpoint` key source, a cap
that no authorizer's `budget` limit answered is `422 budget_refused`;
checks that the cores each candidate's kind needs are configured (Topos
for `topos`; Cella for `program`; Arca for `external`, and Cella too
when a task has checks; Arca for any task with inputs, references or
outputs), which is `422 core_not_configured` with `details.core`
otherwise; and holds the authorizer's limits (spec 004),
`credential_audiences` among them. A minter that answers it keeps no
sign-in it could act from for this caller's later work refuses the
create `403 sign_in_not_kept` (spec 004), so no experiment starts whose
unattended work could not be attributed to its creator. The experiment
is then stored `pending`, with every cell in mode `execute` and none in
mode `import`, and the answer is `201` with `Location`. An installation
with no owner token source, no key source and no file store serves the
v0.1 profile, which changes these checks as The v0.1 profile, below,
says.

An experiment reads as spec 002's fields beside `id`, `owner`,
`created_at` and `updated_at`; its `progress` is computed and never
written. `owner` is the context the create resolved and `created_by`
the caller who created it, which differ for an experiment created in an
organization's context (spec 004). Its `budget` carries `cap_usd_micro`, `spent_usd_micro` and
`remaining_usd_micro` beside `name`, read through the key source (spec
004) when the answer is built and reused for at most
`BUDGET_STATUS_TTL`, so a console shows them without asking Lux; for a
Budget in a currency other than USD it carries `currency` in their
place, and when the key source does not answer, or there is none, they
are left out and the answer is still `200`:

```json
"budget": { "name": "examen-exp_01jb…", "cap_usd_micro": 50000000,
            "spent_usd_micro": 12480000, "remaining_usd_micro": 37520000 }
```

An experiment whose runs hold its external Key (spec 005) also reads, on
`GET /experiments/{id}`, `usage`: what Lux recorded of the calls made
with it so far, read to `read_to`. `unattributed` counts the calls no
trial claims, by its label or a request id it submitted, which count
toward the experiment and no trial:

```json
"usage": { "requests": 41, "cost_usd_micro": 1312000, "unpriced_requests": 0,
           "unattributed": { "requests": 2, "cost_usd_micro": 4100, "unpriced_requests": 0 },
           "read_to": "2026-10-17T10:12:00Z" }
```

In mode `execute`, Examen runs every cell (spec 005). In mode `import`,
Examen starts no trial and runs no smoke trial: each import joins the
cell of its resolved provenance tuple, which the first import of that
tuple makes (spec 002), until the cell holds `trials` trials. A cell
moves `running`, `grading`, `complete`, with no `smoking`. N is still
declared before the first trial arrives, so a cell's sample size is
never chosen after its results are seen. `POST
/experiments/{id}/close` takes no body and ends the intake: every cell
moves on to `grading` with the trials it holds, and the experiment
completes as any does. A close of an experiment in mode `execute` is
`409 wrong_mode`; a repeated close answers `200` and changes nothing.

**Changing an experiment.** `PATCH /experiments/{id}` takes any of
three members. `trials` changes while every cell is `pending`, and is
`409 immutable_field` once any cell has left it (spec 002).
`comparisons`, `independence` and `scheduling` are not among its
members: what an experiment declares is fixed before anything runs,
and a change is a new experiment.
`parallelism` changes until the experiment ends and applies from the
next trial start. `reference` changes at any time, a `complete`
experiment included, with the same rule as at create: automatic
comparisons against the new reference are computed (spec 008),
exploratory once a cell has left `pending`, since that reference was
not declared before the experiment ran, and every earlier comparison
stays readable. A change of
`trials` or `parallelism` to a `complete` or `canceled` experiment is
`409 experiment_finished`.

**Canceling.** `POST /experiments/{id}/cancel` takes no body. It moves
the experiment to `canceled`, parks every cell that is not `complete` as
`canceled`, and cancels each cell's open rollouts at its executor (spec
005). Every trial and measurement recorded so far is kept and stays
readable. The answer is `200` with the experiment. A cancel of a
`canceled` experiment answers `200` and changes nothing; one of a
`complete` experiment is `409 experiment_finished`.

**Deleting.** `DELETE /experiments/{id}` takes `evidence`, one of
`keep`, `trash` and `purge`, required, and `baselines`, `refuse` when
absent or `delete`, and deletes as spec 007 fixes, answering `204`. An
experiment `pending`, `running` or `grading` is `409
experiment_not_finished`; one a baseline record names while `baselines`
is `refuse` is `409 experiment_is_baseline`, with the records in
`details.detail`; one from which another experiment adopted trials is
`409 experiment_adopted_from`, naming those experiments.

**Retrying a cell.** `POST /cells/{id}/retry` takes no body. A cell
parked `blocked` or `over_budget` resumes from the step that parked it,
as spec 005 fixes: a cell blocked by its smoke trials runs them again,
and any other parked cell runs again every index that holds no finished
trial, after its cost check. The answer is `200` with the cell, queued
or parked again. A cell in any other state, a `canceled` one included,
is `409 cell_not_parked`. The question is `cell.retry`, which an
authorizer decides as it decides `experiment.update` (spec 004).

**Trials.** A trial reads as spec 002's fields with `id` and
`created_at`. In a list, each trial also carries `values`, computed
when read: an object from each trial-level metric name of the suite to
the trial's current value of it (spec 007), `null` when it has none. `metric`, a
metric's name or digest, with `value` keeps the trials whose current
value of that metric equals `value` (`true`, `false`, a number or a
label), and with `value=missing` those without one; one without the
other is `400 invalid_field`. `retried=true` lists the trials a retry
replaced, which analysis excludes (spec 002), and `retried=false` the
others; with the filter absent both are listed.

**Measurements.** `generation` is `current` when absent: per trial,
metric and grader version, and per annotator for an annotation grader,
the latest generation, which is the one analysis reads (spec 007).
`all` lists every generation, and an integer lists that generation
alone. `grader` takes a grader digest, `builtin` or `builtin:decline`.

**Re-grading.** `POST /experiments/{id}/regrade` takes `{"grader":
"sha256:…"}` with optional `cells` or `trials`, ids of the experiment;
without either it covers every finished trial of the experiment. The
grader is a version of kind `check`, `model_judge` or `agent_judge`, or
`builtin:decline`, whose metrics the experiment's suite lists; it may be
a newer version than the cells name, which is how a baseline is read at
a candidate's grader (spec 008). Each trial gets the grader's next
generation (spec 006), and the answer is `202` with `{"gradings": n}`. A
grader of level `candidate` takes optional `candidates`, candidate
digests of the experiment, in place of `cells` and `trials`, and each
candidate gets its next generation; `cells` or `trials` with it are `400
invalid_field`. A grader that produces a metric the suite does not list,
an annotation grader, which a person re-grades through the queue, and a
check whose `command`, `workdir` or `env` differ from the version that
ran (spec 006) are each `400 invalid_field` on `grader`; a re-grade of a
canceled experiment is `409 experiment_canceled`.

### Computed answers: the grid and a comparison's results

A console renders an experiment and a comparison from these answers
alone. Every figure in them is computed by Examen's analysis (spec 008)
as measurements arrive and is stored, so a read assembles stored figures
and computes no statistic, and a client computes none either. Both
answers use spec 002's **summary** for one metric over one set of
trials.

**The grid.** `GET /experiments/{id}/grid` answers the candidate × task
grid: one row per task, in the suite version's task order, and in each
row one entry per candidate, in the experiment's candidate order.

```json
{ "experiment": "exp_01jb…", "state": "running", "reference": { "baseline": "bas_01jb…" },
  "metric": { "digest": "sha256:9a40…", "name": "tests_pass", "type": "binary",
              "aggregate": "rate", "direction": "higher_is_better" },
  "candidates": [ { "digest": "sha256:41ab…", "name": "agent-v3-model-a" },
                  { "digest": "sha256:77d0…", "name": "agent-v3-model-b" } ],
  "items": [
    { "task": { "digest": "sha256:0b3e…", "name": "fix-flaky-test" },
      "cells": [
        { "cell": "cel_01jb…", "candidate": "sha256:41ab…", "state": "complete",
          "trials": { "declared": 20, "pending": 0, "running": 0, "checking": 0, "done": 21,
                      "retried": 1, "outcomes": { "completed": 17, "declined": 1, "timed_out": 2, "infra_failed": 1 } },
          "summary": { "aggregate": "rate", "n": 20, "value": 0.85, "numerator": 17, "denominator": 20,
                       "missing": 0, "interval": [0.640, 0.948],
                       "excluded": { "retried": 1 }, "final": true },
          "verdict": "within_noise", "reason": "p = 0.69; q = 0.93 after correcting 131 results at 5%",
          "comparison": "cmp_01jb…" } ],
      "reference_summary": { "aggregate": "rate", "n": 20, "value": 0.80, "numerator": 16, "denominator": 20,
                     "missing": 0, "interval": [0.584, 0.919], "excluded": {}, "final": true } } ],
  "next_cursor": "…" }
```

`metric` is the suite's `primary_metric`, or the suite's metric the
`metric` parameter names. A cell entry carries the cell's `state` and
`parked_reason`, its trials counted by state, by outcome and as
`retried`, the summary of the metric over its trials, and, once its
candidate's comparison is computed, the `verdict` and `reason` of that
comparison's task result for this metric with the comparison's id. The
comparison is the one the `comparison` parameter names for that
candidate, which may be given once per candidate and must name a
comparison of this experiment (else `400 invalid_field`), or else the
candidate's automatic comparison against the experiment's `reference`.
The reference candidate's own column has no verdict. When the reference
is a baseline, each row also carries `reference_summary`, the baseline side's
summary of that task from the automatic comparisons, so a console shows
the baseline as a column. A cell whose summary's `denominator` is below
`MIN_TRIALS_FOR_VERDICT`, on either side, has the verdict
`insufficient` (spec 008). In mode `import` a task row holds an entry
only for the cells imports made. The grid pages by task rows: `limit`
counts rows, and the cursor walks the suite's order. `candidate` keeps
the columns of the candidates it names, `task` keeps the rows of the
tasks it names, and `state` keeps the rows that hold a cell in that
state.

**A comparison** is computed by Examen (spec 008) and never written by a
client. Each candidate other than the reference has an automatic
comparison against the experiment's `reference` (spec 002): computed
from its first finished trials, recomputed in place with `final` false
as trials finish and gradings arrive, and computed a last time with
`final` true when both sides are final. Others are made on request
(below). A grading appended later to a trial that either side of a
final comparison read makes a new comparison of the same pair, and the
earlier one stays. The stream announces each computation. `GET
/comparisons/{id}` answers spec 002's fields with `id` and `owner`, and
`results` holds the suite-level results, one per metric of the suite:

```json
{ "id": "cmp_01jb…", "owner": "https://issuer.example|9ab3",
  "experiment": "exp_01jb…", "candidate": "sha256:41ab…", "baseline": "bas_01jb…",
  "automatic": true, "exploratory": false, "state": "complete", "final": true,
  "variable": ["model"], "confounds": [], "single_variable": true,
  "correction": { "method": "benjamini_hochberg", "primary": "sha256:9a40…", "family": 131 },
  "results": [
    { "level": "suite", "metric": "sha256:9a40…", "metric_name": "tests_pass",
      "direction": "higher_is_better",
      "candidate": { "aggregate": "rate", "n": 840, "value": 0.81, "numerator": 680, "denominator": 840,
                     "missing": 0, "interval": [0.78, 0.84], "tasks": 42, "coverage": 1,
                     "excluded": { "retried": 4 }, "final": true },
      "reference": { "aggregate": "rate", "n": 836, "value": 0.74, "numerator": 615, "denominator": 836,
                     "missing": 0, "interval": [0.71, 0.77], "tasks": 42, "coverage": 1,
                     "excluded": {}, "final": true },
      "delta": 0.07, "delta_kind": "difference", "delta_interval": [0.03, 0.11],
      "method": "stratified_permutation", "statistic": "difference", "exact": false, "resamples": 10000,
      "p": 0.0003, "q": 0.0003, "verdict": "improved",
      "reason": "p < 0.001 for the primary metric, tested alone without correction",
      "left_out": [], "confounds": [] } ],
  "computed_at": "2026-10-17T09:12:44Z" }
```

`GET /comparisons/{id}/rows` pages the task-level results of the same
shape, `level: task` with `task` and `task_digests`, ordered by metric
in the suite's order and then by task in the suite's order. `metric`,
`task` and `verdict` narrow them. A result's members are spec 002's,
and `correction` names the method spec 008 applies, the primary metric
whose suite-level result is tested alone, and how many p-values the
corrected family held. A comparison's reference side
is its summaries alone: reading a comparison gives no access to the
reference experiment's trials, measurements or evidence (spec 004).

**Declared comparisons.** Each comparison an experiment declared at
create is made with it, `automatic` false unless it is the automatic
comparison's own pair in its orientation, declared with no `metric` of
its own, `declared` its position in the experiment's `comparisons` and
`exploratory` false, and is computed and recomputed as the automatic
comparison is (spec 008). One of the general form carries its
`declaration`, and its results name their strata (spec 008). `declared`
on a comparison list keeps the declared comparisons, or with `false`
the others. Its primary result carries its `p` and no `q` or verdict:
the declared analysis holds them.

**The declared analysis.** `GET /experiments/{id}/declared` answers
spec 002's declared analysis:

```json
{ "experiment": "exp_01jb…", "final": true,
  "family": { "method": "benjamini_hochberg", "size": 11, "level": 0.05 },
  "comparisons": [
    { "index": 0, "comparison": "cmp_01jb…", "metric": "sha256:9a40…",
      "p": 0.0031, "q": 0.017, "verdict": "changed",
      "reason": "p = 0.0031; q = 0.017 after correcting the primary results of 11 declared comparisons at 5%",
      "final": true } ],
  "independence": { "metric": "sha256:9a40…", "metric_name": "kind",
                    "method": "stratified_permutation", "statistic": "pearson_x2_sum",
                    "p": 0.004, "q": 0.004, "verdict": "changed",
                    "reason": "p = 0.004 for the experiment's declared test of independence, tested alone without correction" },
  "computed_at": "2026-10-17T09:12:44Z" }
```

Before any declared comparison is computed it answers each entry with
its index, its metric and the reason "not computed yet: the candidate
has no finished trial", and `final` false. An experiment that declared
nothing answers a family of size 0 and no entries. Like every computed
answer, it is assembled from stored figures.

**A comparison on request.** `POST /comparisons` takes `{"experiment":
"exp_…", "candidate": "sha256:…", "baseline": "bas_…"}`, or in place of
`baseline` a `reference_candidate`, another candidate of the same
experiment, and optionally `variable`, one logical variable of spec 008.
A comparison across tasks takes `"variable": "task"` with `task` and
`reference_task`, the names of two tasks of the experiment's suite, in
place of a reference: the candidate's cell of `task` is compared with
its cell of `reference_task` (spec 008).
The answer is `201` with the comparison in state `computing`, with
`automatic` false and `exploratory` true: it was not declared before
the experiment ran, so its primary metric is corrected with every other
result and it is never headlined (spec 008). It is computed once, from
what both sides hold then, with `final` as they stand, and is not
recomputed. A body
with more than one reference or none, `reference_task` without
`"variable": "task"` or the reverse, two equal tasks, and a `variable`
outside spec 008's table, are `400 invalid_field`; a task the
candidate holds no cell of is `422 not_in_experiment`; a candidate the experiment does not
hold is `422 not_in_experiment`; a baseline of another suite is `422
suite_mismatch`.

### Imported trials

```json
POST /experiments/{id}/imports
{ "task": "sha256:0b3e…", "candidate": "sha256:41ab…",
  "executor": "topos", "executor_ref": "ses_01M34G2JF01B91B8399CD1G6YP" }
```

This imports one finished Topos session (`executor: topos`) or Cella
sandbox (`executor: cella`) as a trial of an experiment in mode
`import`. Examen reads the record at its core as the owner (spec 004)
and resolves its provenance tuple (spec 005), which must equal the
tuple the named task and candidate give. The trial joins the cell of
that tuple, made by this import when the experiment has none, at the
cell's next index (spec 002). The answer is `201` with the trial,
`imported: true`. Its graders then run as on any trial (spec 006).

| Case | Answer |
|---|---|
| the experiment is in mode `execute` | `409 wrong_mode` |
| the experiment's intake is closed, or it is `complete` or `canceled` | `409 experiment_finished` |
| the task or the candidate is not part of the experiment | `422 not_in_experiment` |
| the session or sandbox does not exist, or the owner cannot read it | `422 reference_not_found` on `executor_ref` |
| it has not finished | `409 source_not_finished` |
| it is already a trial of this experiment | `409 already_imported` |
| the cell already holds `trials` trials | `409 cell_full` |
| its records differ from the tuple of the task and candidate, or do not pin a field | `422 provenance_mismatch`, `details.fields` naming each tuple field |

**An external harness's past trial** is imported with `executor:
external`, so a study run before Examen existed, or outside it, is
backfilled and graded like any trial:

```json
POST /experiments/{id}/imports

### External trials

An external harness runs the trials of a candidate of kind `external`
wherever it likes (spec 005). It leases pending trials, runs each, and
submits each one's outcome and outputs; Examen then grades the trial as
it grades an executed one. The external harness calls these routes as any client
does, with a bearer of a subject the authorizer lets act on the
experiment.

```json
POST /experiments/{id}/work/lease
{ "candidate": "sha256:41ab…", "max": 4 }
```

| Member | Rule |
|---|---|
| `candidate` | optional; a candidate of the experiment of kind `external`, whose trials alone the lease takes. One of another kind is `400 invalid_field`; one the experiment does not hold is `422 not_in_experiment`. Absent, the lease takes trials of every `external` candidate of the experiment, and the question `trial.lease` carries no `candidate` and no `harness` (spec 004) |
| `max` | optional; the most trials to lease, 1 or more; absent, every trial the call may lease |
| `renew` | in place of `candidate` and `max`: a lease id, `lse_…`, whose trials the caller still holds |

A lease takes the pending trials, of its candidate or of every
external candidate, that their cells' open rollouts may run now, within
each rollout's share of the experiment's parallelism less the trials
already leased or checking, and never more at once than the
parallelism, in the order the experiment's `scheduling` deals them, so
a cell's smoke trials come first and its main trials only after its
cost check (spec 005). The answer is `200`:

```json
{ "lease": "lse_01jb…", "expires_at": "2026-10-17T10:10:00Z",
  "model_key": "lux_…",
  "trials": [
    { "id": "tri_01jb…", "cell": "cel_01jb…", "index": 0,
      "lux_labels": "examen.trial=tri_01jb…",
      "candidate": { "name": "extractor-high", "digest": "sha256:41ab…",
                     "external": { "harness": "extractor", "version": "2.1.4",
                                   "model": "provider-model-2026-01", "reasoning": "high" } },
      "task": { "name": "invoice-17", "digest": "sha256:0b3e…" },
      "instruction": "Extract the invoice fields into fields.json.",
      "inputs": [ { "name": "invoice.pdf", "url": "https://arca.example/…",
                    "digest": "sha256:5d1c…", "size": 182044 } ],
      "outputs": ["fields.json"],
      "timeout": "30m", "max_turns": 40 } ] }
```

Each trial carries the candidate it runs, by `name` and `digest` with
the `external` configuration its harness declared (spec 002), so a
harness that leased without naming a candidate knows what to run; its
task's `instruction` when it has one, its `outputs`, its resolved
`timeout` and its `max_turns` when set, and one
presigned link per input from Arca's materialize route, each with the
input's digest and size (spec 005). It carries no reference: references
reach only the check sandbox. Each trial carries `lux_labels`, the value
of the `Lux-Labels` header each of its model calls sends,
`examen.trial=<trial id>`. With a key source, a lease and a renewal also
carry `model_key`, the experiment's external Key, which the trials'
model calls go through so the experiment's Budget binds them and their
cost is read (spec 005); the answer is sent with `Cache-Control:
no-store`, and no other answer carries the Key: a lease sent with an
`Idempotency-Key` keeps its answer without it, and a repeat is answered
the Key afresh. The Key is asked of the
key source before any trial is taken: a source that refuses answers `403
forbidden` with its reason as `details.reason`, one whose Budgets have
nothing left `422 budget_refused`, and one that does not answer `503
owner_tokens_unavailable` with `details.reason` `key_source`, each
taking no trial. `expires_at` is `EXTERNAL_LEASE` after the
call. When nothing may be leased now, the answer is `204`. A renewal
answers `200` with the trials the lease still holds and a new
`expires_at`, `EXTERNAL_LEASE` after the renewal, and no input links.
A lease that lapses returns its trials to pending, where another lease
may take them; a renewal or a submit under it is `409 lease_expired`. A
renewal of a lease another subject holds is `409 lease_not_held`. A
lease on an experiment in mode `import` is `409 wrong_mode`, and on one
`complete` or `canceled` `409 experiment_finished`.

```json
POST /trials/{id}/submit
{ "lease": "lse_01jb…",
  "outcome": "completed",
  "started_at": "2026-10-17T10:01:02Z", "agent_ended_at": "2026-10-17T10:03:40Z",
  "outputs": [ { "path": "fields.json", "data": "eyJ0b3RhbCI6IDEyMy40NX0=" } ],
  "final_message": "Extracted 14 fields.",
  "lux_requests": ["req_01jb…", "req_01jb…"],
  "service_versions": { "lectio": "v0.7.0" },
  "measurements": [ { "metric": "sha256:6e02…", "value": 0.93 } ],
  "ref": "run-8812" }
```

| Member | Rule |
|---|---|
| `lease` | required; the lease the trial is held under |
| `outcome` | required; any outcome of spec 002 but `canceled` |
| `failure` | `{code, detail}`; required with `infra_failed` and `over_budget`, absent otherwise |
| `started_at`, `agent_ended_at` | required; the system under test's first step and its end, the first no later than the second; they fill the trial's fields of the same names, and Examen sets `ended_at` once the checks and evidence are done |
| `outputs` | optional; each names one of the task's `outputs` by `path`, at most once, and carries it as `{path, data}`, a file output's bytes in standard base64 inside the body, which `MAX_REQUEST_BYTES` bounds, or as `{path, arca: {path, digest}}`, an object the external harness wrote into the owner's Arca space: the file itself for a file output, and for a directory output, which is never inline, a tar archive of it, optionally gzip-compressed (spec 005). A path the task does not name, and `data` for a directory output, are `400 invalid_field`; an Arca object the owner cannot read, or whose digest differs, is `422 reference_not_found` on it |
| `transcript`, `final_message` | optional; the trial's transcript as JSONL text and the system under test's last message, which judges read (spec 006) |
| `lux_requests` | optional; the Lux request ids of the trial's model calls. A record of the experiment's external Key with one of these ids is the trial's whatever label it carries; absent, the trial's records are those that carry the request label `examen.trial=<trial id>` (spec 005) |
| `service_versions` | optional; an object from a service's name to its version, each a string of at most 63 characters (spec 005) |
| `service_usage` | optional; an object from a service's name, at most 63 characters, to `{cost_usd_micro, units}`: what that API reported its own usage of the trial to be, a non-negative integer of micro-dollars and an object from a unit's name, at most 63 characters, to a non-negative number (spec 005) |
| `declared` | optional; `{harness_version, image}`, each a string of at most 255 characters: the external harness's own version for this run, which equals the candidate's `version` or the request is `422 provenance_mismatch` naming `version`, and the image it ran in, a tag or a digest kept as declared (spec 005) |
| `measurements` | optional; each `{metric, value, rationale}`, a value the external harness computed itself, of a metric the suite lists that no grader produces for the trial's task, typed by its metric; stored under `self:<harness>` with `self_reported` true (spec 007). A metric the suite does not list, or one a grader produces for the task, is `400 invalid_field` |
| `ref` | optional; the external harness's own reference for the trial, at most 255 characters, kept as the trial's `executor_ref` |

The answer is `200` with the trial: `checking` when its task has
checks, which then run in the check sandbox (spec 005), and `done`
otherwise. The submit ends the lease on that trial. A trial not held
under the lease named, because another lease or none holds it, a
subject other than the lease's submits, or the trial was canceled
while leased, is `409 lease_not_held`; a lapsed lease is `409
lease_expired`. A submit repeated with the same lease and the same body
after it succeeded answers `200` with the trial and changes nothing.

### Annotation queue

A grader of kind `annotation` has a queue of annotation items (spec
002): the trials sampled for it, and those the owner queues (spec 006).

| Method and path | Purpose | Answers | Action asked |
|---|---|---|---|
| `GET /annotations` | queue items; `grader` (a digest), `experiment`, `state` (`open` when absent, `claimed` or `done`), `owner`, `limit`, `cursor` | 200, 400, 403 | `annotation.list` |

An item reads as `{grader, trial, experiment, cell, task, state,
claimed_by, claimed_until, instructions, produces, evidence,
sampled_at}`: the annotation item of spec 002, its trial's experiment,
cell, task and evidence references (spec 007), and the grader's
`instructions` and `produces`. A claim answers `200` with the item, or

```json
POST /annotations
{ "grader": "sha256:5e61…", "trial": "tri_01jb…",
  "values": [ { "metric": "sha256:9a40…", "value": 4,

```

the grader produces, each recording its submitter as `annotator`,
`human:<subject>` (spec 006). A metric of the grader without a value is

they were. The answer is `201` with the measurements.

**Creating** takes the publication's `kind`, `name`, `title`,
`description`, `visibility` (`private` when absent, or `unlisted`) and,
for a benchmark, `submissions`, beside its first version's members:

```json
POST /publications
{ "kind": "report", "name": "cross-harness-n50",
  "title": "One model, two harnesses, 50 trials per cell",
  "visibility": "unlisted",
  "source": { "report": "rep_01jb…" },
  "evidence_level": "outputs",
  "attribution": "Example Lab" }
```

| Member | Rule |
|---|---|
| `source` | required; `{report}` for a `report`, `{suite}` (a suite digest) for a `benchmark`, `{export}` for a `dataset`, the context owner's, else `422 reference_not_found`; another form than the kind's is `400 invalid_field` |
| `evidence_level` | optional; `aggregates` when absent, `outputs` or `full`; a benchmark's other than `aggregates` is `400 invalid_field` |
| `exclude` | optional; evidence paths to leave out, as a blocked version's `scan` names them |
| `dataset` | required for a `dataset`, else absent: `{license, citation}`, as spec 013 checks them |
| `attribution` | optional; the name the version shows for its owner, at most `PUBLICATION_LINE_MAX_BYTES`, which an authorizer's `attribution` limit replaces (spec 004); with neither, the version names no owner and its `attribution` is `null`, never the owner's subject (spec 013) |

A `visibility` of `public` is `400 invalid_field`: a publication becomes
public only through a listing. A name the owner already uses for a
publication of the kind is `409 publication_exists`. Evidence that
would exceed `PUBLICATION_EVIDENCE_MAX_BYTES` is `422 limit_exceeded`;
a version on an installation without Cella, which runs every version's
secret scan, or at `outputs` or `full` without Arca, is `422
core_not_configured`; and a version at `outputs` or `full` on an
installation that does not declare its file store download-only
(`EXAMEN_FILESTORE_DOWNLOAD_ONLY`, spec 011) is `422
file_store_not_download_only`, each before anything is written. The
answer is `202` with the publication and its version, which is
`preparing`, since every version's snapshot is scanned (spec 013); a
client reads `GET /publications/{id}/versions/{n}` until it leaves
`preparing` and `scanning`. `link` is in an answer only for a caller
allowed `publication.update`: `GET /publications/{id}` asks it after
`publication.read`, and a deny leaves `link` out and changes nothing
else (spec 004).

**A new version** takes the version members above. The publication's
`kind` decides the form of `source`. Withdrawing answers `200` with the
version `withdrawn`; a withdrawal of a version that is not `published`
is `409 version_not_published`, and a repeated withdrawal `200`.

**Visibility.** A `PATCH` of a `public` publication's `visibility` is
`409 publication_listed`: its listing is ended first. A `PATCH` to
`private`, and a replaced link token, of a publication with files
replace its versions' Arca links (spec 013). A listing of a
publication with no `published` version is `409 version_not_published`;
a listing of a benchmark whose `submissions` is not `reviewed`, and a
`PATCH` of a listed benchmark's `submissions` to another value, are
`409 benchmark_not_reviewed`; a listing of a benchmark version that
holds two accepted entries of one owner other than the benchmark's is
`409 owner_has_entry` (spec 013).
A deny of `publication.list` or `publication.pause`, asked after
`publication.read` let the same caller see the publication, is `403
forbidden` with the authorizer's reason (spec 004). A repeated listing,
end of listing, pause or resume answers `200` and changes nothing.

**A benchmark's reference.** A `PATCH` with `reference`, a submission
id, makes that submission the reference of the benchmark version it is
accepted to (spec 013), and the version's results table is computed
again. A submission that is not an accepted entry of the publication is
`422 reference_not_found`, and `reference` on a publication that is not
a benchmark is `400 invalid_field`.

**Results**, after v0.1. `GET /publications/{id}/results` answers a benchmark
version's results table as last computed (spec 013), its latest
`published` version unless `version` names another, in one answer,
since a version holds at most `MAX_BENCHMARK_ENTRIES` entries:

```json
{ "publication": "pub_01jb…", "version": 1,
  "primary_metric": "sha256:77aa…",
  "reference": "sbm_01jd…",
  "method": { "test": "stratified_permutation", "statistic": "difference", "adjustment": "holm",
              "level": 0.95, "pairs": 3, "resamples": 10000,
              "inputs_digest": "sha256:0b4e…", "seed": "5d0c…",
              "computed_at": "2026-10-18T09:12:03Z" },
  "common": { "tasks": ["t1", "t2", "t4", "t5"], "coverage": 0.9 },
  "entries": [
    { "id": "sbm_01je…", "entry": { "attribution": { "name": "Example Lab" }, … },
      "report": { "publication": "pub_01jc…", "version": 2 },
      "summary": { "aggregate": "rate", "value": 0.82, "interval": [0.74, 0.88], "tasks": 4, "coverage": 0.9, … },
      "order": 1, "rank": { "low": 1, "high": 2 },
      "vs_reference": { "delta": 0.12, "interval": [0.01, 0.23], "p": 0.03, "h": 0.06,
                        "verdict": "within_noise",
                        "reason": "p = 0.03 unadjusted; h = 0.06 after Holm's adjustment over 3 pairs at 5%",
                        "confounds": [ { "name": "window",
                                         "candidate": { "from": "2026-09-02T08:00:00Z", "to": "2026-09-03T17:10:00Z" },
                                         "reference": { "from": "2026-10-11T09:00:00Z", "to": "2026-10-11T21:40:00Z" } } ] } },
    { "id": "sbm_01jd…", "entry": { … }, "report": { … }, "summary": { … },
      "order": 2, "rank": { "low": 1, "high": 3 } },
    { "id": "sbm_01jf…", "entry": { … }, "report": { … }, "summary": { … },
      "order": 3, "rank": { "low": 2, "high": 3 }, "vs_reference": { … } } ],
  "unranked": [
    { "id": "sbm_01jg…", "entry": { … }, "report": { … },
      "why": "covers 60% of the suite's weight; 80% needed; left out: t3 (1 trial)" },
    { "id": "sbm_01jh…", "entry": { … }, "report": { … },
      "why": "20 of 20 primary values are self-reported" } ] }
```

Each entry is a submission's `id`, its `entry` without `values`, which
`GET /submissions/{id}` answers, its report's `{publication, version}`,
`summary`, its suite-level summary of the primary metric over the
table's common tasks, which the order reads, its `order` and `rank`
(spec 013), and, on every entry but the reference, `vs_reference`: spec
008's pair result of the entry against the reference entry, its
`delta`, `interval`, `p`, `h`, `verdict`, `reason` and `confounds` as
spec 002's result members. The verdict follows `h`, the value Holm's
procedure adjusted across every pair of the table, never the
unadjusted `p`, which the reason shows as text: in the example the
first entry's `p = 0.03` against the reference is `h = 0.06` across the
three pairs, so it is `within_noise`, as its rank interval, which still
reaches the reference's place, says. `common` names the tasks every
ranked entry is compared over and the share of the suite's weight they
hold (spec 008). `unranked` holds the entries whose primary values are
missing or self-reported, and those below `MIN_TRIALS_PER_TASK_IN_SUITE`
or `MIN_SUITE_COVERAGE` alone or with the table's common tasks, each
with `why` and no `order`, `rank` or `vs_reference`. `reference` is the
version's reference submission, `null` when it has none, and then no
entry carries `vs_reference`. `method` names the test,
`stratified_permutation`, and its statistic; the adjustment, `holm`;
`level`, the `CONFIDENCE_LEVEL` the rank intervals and every pair's
verdict hold together at, adjusted at 1 − `level`; `pairs`, the
K(K − 1) / 2 pairs adjusted together; `resamples`,
`PERMUTATION_RESAMPLES` as resolved for them; the table's
`inputs_digest` and `seed`; and `computed_at`. A publication that is
not a benchmark is `400 invalid_field`.

**Two entries**, after v0.1. `GET /publications/{id}/results/compare?a=<submission>&b=<submission>`
answers the stored pair result of two accepted entries of one version,
the one `version` names or the latest `published` one, with `a` as the
candidate side: `{publication, version, a, b, delta, interval, p, h,
verdict, reason, confounds, method}`: the stored pair's figures, the
same the reference column shows when one of the two is the reference,
negated when `a` and `b` are read the other way round. `method` is the
table's, with `note`, the fixed sentence "One pair of the table: its
verdict follows the value adjusted for every pair, h." A pair with an
unranked entry answers `insufficient` with its reason. `a` or `b` missing, or the two equal,
is `400 invalid_field`; an id that is no accepted entry of the version
is `404 submission_not_found`; a publication that is not a benchmark is
`400 invalid_field`.

|---|---|

### Public reads

The routes under `/public/` serve published versions to a reader who
does not sign in: the snapshot and its evidence links, never a live
object (spec 013). They take no bearer and ignore one sent. No answer
of these routes carries a subject anywhere in its body: no
`published_by`, `withdrawn_by`, `owner` or `created_by`, and none
inside a snapshot (spec 013).

| Method and path | Purpose | Answers | Action asked |
|---|---|---|---|
| `GET /public/publications/{key}` | a publication's latest `published` version with its snapshot and evidence links, or the one `version` names | 200, 400, 404, 410, 429 | `publication.read`, with no subject |
| `GET /public/publications/{key}/versions` | its versions: `number`, `digest`, `state`, `published_at`, `withdrawn_at` | 200, 404, 410, 429 | `publication.read`, with no subject |
| `GET /public/publications/{key}/results` | a benchmark version's results table, as `GET /publications/{id}/results` answers it; `version` | 200, 400, 404, 410, 429 | `publication.read`, with no subject |
| `GET /public/publications/{key}/results/compare` | the pair result of two entries, as `GET /publications/{id}/results/compare` answers it; `a`, `b`, `version` | 200, 400, 404, 410, 429 | `publication.read`, with no subject |
| `GET /public/listings` | the listed publications, the newest listing first; `kind`, `limit`, `cursor` | 200, 400, 429 | `publication.read`, with no subject, for each item |

`{key}` is a link token, which resolves while the publication is
`unlisted` or `public`, or a publication's id, its public id, which
resolves while it is `public`. A key that resolves to nothing, and a
deny of the question, answer `404 publication_not_found`, byte for byte
alike, and no error from these routes carries the key in `details`. A
pinned version that was withdrawn, and a publication whose every
version was withdrawn, answer `410 publication_withdrawn`; a paused
publication answers `410 publication_paused`. A listing leaves out an
item whose question is denied. The answer:

### The progress stream

Every change of state of an experiment, of its cells and of its trials,
every grader generation finished on a trial, every comparison computed
or recomputed, and every bar evaluation completed on one of its
comparisons is written to the experiment's event log as an event (spec
002), in the same transaction as the change, with the experiment's next
sequence number, starting at 1. A change that ends the experiment also
writes `experiment.completed` or `experiment.canceled`, and a cell that
parks also writes `cell.parked`: the sink events below. A state read
through the API therefore never lacks its event. The log is kept as
long as the experiment (spec 007).

`GET /experiments/{id}/events?after=<seq>` reads the log as JSON, oldest
first: `{"items": [{id, seq, type, data, at}], "next_cursor":
"<seq>"}`, with `after` as its cursor. `GET /experiments/{id}/stream`
serves the same log as server-sent events, with `Content-Type:
text/event-stream` and `Cache-Control: no-store`. Any replica serves
either route. A stream reads the log and looks for new entries every
`STREAM_POLL_INTERVAL`, so it needs no affinity to the replica that made
a change.

```
id: 4182
event: trial
data: {"id":"tri_01jb…","cell":"cel_01jb…","index":3,"state":"done","outcome":"completed"}

```

| Event | `data` | Sent |
|---|---|---|
| `snapshot` | the experiment as `GET /experiments/{id}` answers it | first, on a stream opened without `Last-Event-ID`; its `id` is the latest sequence at that moment |
| `experiment` | `{id, state, progress}` | on each change of the experiment's state |
| `cell` | `{id, task, candidate, state, parked_reason}` | on each change of a cell's state |
| `trial` | `{id, cell, index, state, outcome, retry_of, imported}` | on each change of a trial's state |
| `graded` | `{trial, grader, generation, metrics}`, `metrics` the count of measurements appended | when one grader generation finishes on one trial |
| `comparison` | `{id, candidate, baseline, reference_candidate, automatic, declared, final}`, `declared` a declared comparison's position and absent otherwise | when a comparison is computed, and each time a provisional one is recomputed |
| `experiment.completed`, `experiment.canceled`, `cell.parked` | the sink event's `data` (below) | beside the `experiment` or `cell` event of the change |
| `bar.passed`, `bar.failed` | the bar evaluation's summary of spec 009 | when a bar evaluation of one of its comparisons completes |
| `end` | `{state}` | last, once the experiment is `complete` or `canceled` and every earlier event is sent; the server then closes the stream |
| `error` | an error envelope | before the server closes a stream it may no longer serve |

`snapshot`, `end` and `error` are frames of the stream, not events of
the log, and carry no sequence of their own.

A stream opened with `Last-Event-ID` replays every event after it, in
order, then continues live: no event is skipped and none is sent twice,
across a reconnect to another replica included. A `Last-Event-ID` above
the experiment's latest sequence is `400 invalid_cursor` before the
stream starts. When nothing has been sent for `STREAM_KEEPALIVE`, the
server sends the comment line `: keepalive`.

A stream asks `experiment.read` when it opens. While open, it asks again
before the first event after its cached decision lapses (spec 004); a
deny sends an `error` event with `experiment_not_found` and closes. The
stream closes at the expiry of the bearer it was opened with, sending
nothing after it, and the client reconnects with a fresh token and
`Last-Event-ID`. One subject holds at most `MAX_STREAMS_PER_SUBJECT`
streams on one replica; one more is `429 too_many_streams`. A replica
that shuts down closes its streams without `end` (spec 011), and the
client reconnects.

### The event sink

An installation can receive every experiment's sink events at one
address and act on them outside Examen: release what it holds for an
experiment when it completes or is canceled, tell an owner that a cell
parked and why, raise an alert when a bar fails (spec 009). The sink
events are `experiment.completed`, `experiment.canceled`,
`cell.parked`, `bar.passed` and `bar.failed`, journaled in their
experiment's log, and `publication.published`,
`publication.withdrawn` and `listing.requested` (spec 013), journaled
in their publication's own log, so an installation's listing queue and
public pages learn of a change at once (spec 002). Each is journaled in
the same transaction as its change and delivered as journaled; a
publication event carries `publication` in place of `experiment`.

```json
{"id": "evt_01jab...", "experiment": "exp_01jab...", "seq": 4211,
 "type": "cell.parked", "at": "2026-10-17T10:41:00Z",
 "owner": "https://issuer.example|9ab3",
 "data": {"id": "cel_01jab...", "task": "sha256:...", "candidate": "sha256:...",
          "state": "over_budget", "parked_reason": "budget_exhausted"}}
```

| Type | `data` |
|---|---|
| `experiment.completed`, `experiment.canceled` | `{id, state, budget, created_by}`: the experiment, its Lux Budget's name and the subject that created it |
| `cell.parked` | `{id, task, candidate, state, parked_reason}` |
| `bar.passed`, `bar.failed` | the bar evaluation's summary (spec 009) |
| `publication.published`, `publication.withdrawn`, `listing.requested` | `{id, version, kind, visibility, owner}`: the publication, the version the change is about, its kind and visibility |

A sink event carries ids, names, digests, states, verdicts and figures.
It never carries a transcript, a final message, a file, a check's
output, a judge's rationale, a task's instruction or a credential.

**Signing.** `EXAMEN_EVENTS_URL` (spec 011) receives a `POST` with
`Content-Type: application/json`, the event as journaled, byte for
byte, and

```
Examen-Signature: t=<unix seconds of this attempt>,v1=<hex HMAC-SHA256 of "<t>.<body>" under the first secret>[,v1=<the same under the second>]
```

The file `EXAMEN_EVENTS_SECRET_FILE` names (spec 011) holds one secret,
or two separated by a comma while a secret is rotated, and then both
signatures are sent. The signature is recomputed on every attempt. A
sink verifies by recomputing the HMAC over the exact bytes, comparing
in constant time against each `v1`, and refusing a `t` more than
`SIGNATURE_MAX_AGE` from its own clock. This is the format Cella and
Lux sign their events with, so one sink verifies all three.

**Delivery** runs on one replica at a time: the holder of the delivery
lease, one row in Postgres that a replica takes in a transaction when
it is free or its holder has not renewed it within `DELIVERY_LEASE`,
and renews well inside that time. No session-level advisory lock is
used, since a pooler in transaction mode does not keep one (spec 011).
Delivery is at least once, in journal order per experiment. An event's
`delivery` is `pending` until it is acknowledged or dropped.

| Answer | Then |
|---|---|
| 2xx | acknowledged |
| 408, 429, 5xx, a connection failure, or no answer within `DELIVERY_TIMEOUT` | retried with exponential backoff from `DELIVERY_BACKOFF_MIN` to `DELIVERY_BACKOFF_MAX` |
| 401 | retried the same way and logged at error: the two ends hold different secrets, and dropping would lose every event of a botched rotation |
| any other 4xx | dropped at once and counted: a sink that refuses the body will refuse it again |
| still unacknowledged after `DELIVERY_RETRY_WINDOW` | dropped, counted and logged |

A URL without a secret, a secret without a URL, and a non-loopback
`http://` URL each stop the start (spec 011). Without a URL, sink
events are journaled with `delivery` `acknowledged` and nothing is
sent. Delivery is built after v0.1 (Build order, below); until a
release delivers sink events, `serve` refuses to start while
`EXAMEN_EVENTS_URL` is set, so no installation believes it receives
events that are never sent (spec 011).

Examen keeps no per-owner webhook address or secret. Each event names
its owner, and an installation serving many owners routes each event to
the owner's chosen destination in its sink.

### Idempotency

| Request | Repeated with the same content |
|---|---|
| `PUT` of a versioned object | answers `200` with the same version; no version is made (above) |
| `PUT` of a baseline | answers `200` with the current record when it names the same experiment and candidate |
| `PUT` of a share | answers `200` with the share |
| `PUT` of a taxonomy | answers `200` with the current record when its content is the same |
| `PUT` or `DELETE` of a listing, a pause, a resume, a withdrawal | answers `200`; nothing changes |
| `POST /submissions` | answers `200` with the submission already made of that report version and candidate |
| `POST /experiments/{id}/cancel` | answers `200`; the experiment stays `canceled` |
| `POST /experiments/{id}/close` | answers `200`; the intake stays closed |
| `POST /trials/{id}/submit` | answers `200` with the trial when the same lease and body already succeeded |
| `POST /cells/{id}/retry` | once the cell has left its parked state, `409 cell_not_parked`; a cell is resumed once |
| `POST .../evaluate` | answers `200` with the evaluation already made of that comparison with the same `metadata` |

`POST /experiments`, `POST /experiments/{id}/imports`, `POST
/experiments/{id}/work/lease`, `POST /experiments/{id}/regrade`, `POST
/comparisons`, `POST /exports`, `POST /annotations`, `POST
/annotations/queue`, `POST .../evaluate`, `POST
/experiments/{id}/reports`, `POST /reports/{id}/draft`, `POST
/reports/{id}/exports`, `POST /publications`, `POST
/publications/{id}/versions` and `POST /submissions` take an
`Idempotency-Key` header of 1 to
`IDEMPOTENCY_KEY_MAX_BYTES` bytes of visible ASCII. The same key from
the same subject on the same route within `IDEMPOTENCY_WINDOW` answers
the first response again, its status and body, with
`Idempotent-Replayed: true`, and creates nothing. The same key with a
body whose canonical JSON differs, and the same key from the same
subject on another route, are `409 idempotency_key_reused`. A first
request answered with a `5xx` keeps no answer, so its retry runs again.

The first request reserves its key for `IDEMPOTENCY_RESERVATION`. A
repeat that arrives while the reservation holds and the first request
is still being served is `409 request_in_progress`, retryable. The
reservation lapses so that a repeat runs when the replica serving the
first stopped mid-request. A request that carries the header is served
within `REQUEST_DEADLINE`, shorter than `IDEMPOTENCY_RESERVATION`, and
one past it is abandoned, its transaction rolled back, and answered
`503 unavailable`: so a first request never commits after its
reservation lapsed and a repeat began. Keys are stored in Postgres, so
the rule holds across replicas and restarts. A request without the
header is not deduplicated.

### Errors

```json
{ "error": {
    "code": "limit_exceeded",
    "message": "This request is larger than this service allows.",
    "details": {
      "detail": "experiment create: 120 tasks × 20 candidates = 2400 cells exceed MAX_CELLS_PER_EXPERIMENT",
      "constant": "MAX_CELLS_PER_EXPERIMENT",
      "field": "candidates",
      "retryable": false } } }
```

One `code` to branch on; one fixed sentence for a person in `message`,
the same for every occurrence of the code; and `details` for a
developer. `message` never carries what `details` carries.

| `details` member | Type | Present | Meaning |
|---|---|---|---|
| `detail` | string | on every error but `internal` | the developer detail: the operation, the object, the observed and the expected value, and the error from the layer below |
| `retryable` | bool | always | whether the same request may succeed later unchanged |
| `field` | string | when the error is about one member or parameter | a dotted path with indexes, such as `candidates[1]` or `values[0].value`, or a parameter's name |
| `constant` | string | on `limit_exceeded` | the constant of spec 002 the request exceeds |
| `reason` | string | on `invalid_token`, `forbidden` and `owner_tokens_unavailable`, and on a code an authorizer's deny reason named (spec 004) | one snake_case word for this instance: the verifier's word, the authorizer's deny reason, the limit's member, or the minter's or key endpoint's refusal (spec 004) |
| `figure` | number | on a `forbidden` a limit made | the figure the limit holds (spec 004) |
| `state` | string | on a conflict with an object's state | the object's state |
| `fields` | []string | on `provenance_mismatch` | the tuple fields that differ or are not pinned |
| `core` | string | on `core_not_configured`, `core_unavailable`, `core_timeout` | `topos`, `cella`, `lux`, `arca` or `origo` |

An error nobody classified is `500 internal`: its text is logged and
not returned. No error carries any part of a token, a Lux Key or another

mapped to `422 reference_not_found`, so a core's refusal reads as the
object being out of reach, and never passes through as Examen's own.

### The v0.1 profile

An installation with no owner token source (neither a minter nor
`EXAMEN_SOLE_OWNER`), no key source and no file store (no
`EXAMEN_ARCA_URL`) serves the v0.1 profile, which is also everything
the first release serves (spec 011): the versioned objects; experiments
whose candidates are all of kind `external`, in mode `execute` or
`import`, with their grid, cells, trials, measurements, comparisons and
rows, comparisons on request, events and stream, change, cancel, close,
cell retry and delete; the lease, renewal and submit of external
trials; the import of an external harness's past trials; the values an
external harness reports for itself, stored self-reported and never
headlined (spec 007); and `GET /openapi.yaml`. Nothing in it calls a
core as the owner, so no owner token is ever minted for its work.

An experiment's create in the profile:

- resolves only the pins a served path uses. An `external` candidate's
  fields are its external harness's declaration and are never
  resolved, and a task's workspace, which no external trial starts
  from, and its environment image, which only a check sandbox would use,
  are checked in form, as at an apply. No pin
  is resolved at a core and the minter is not asked, so
  `unresolved_reference`, `image_not_admitted` and `sign_in_not_kept`
  do not arise;
- refuses a candidate of kind `topos` or `program` `422
  core_not_configured`, with `details.core` `topos` or `cella`;
- refuses a suite any of whose graders, its `decline_judge` and its
  `canonicalizers` included, is of kind `check`, `model_judge` or
  `agent_judge` `422 core_not_configured`, with `details.core` the core
  that grader would need: `cella`, `lux` or `topos`. The built-in
  decline judge calls no model and is served (spec 006);
- refuses a task with inputs or references `422 core_not_configured`,
  with `details.core` `arca`: inputs are copied into the experiment's
  folder in the file store before the first lease, and references
  reach only checks. A task with outputs is served;
- records the Budget an authorizer's allow assigns as `limits.budget`
  with no request to Lux. Without that limit, it records the spending
  cap `budget.cap_usd_micro` gives as the experiment's `budget`, with
  no Budget made for it, since nothing the profile serves calls a model
  through Examen, and refuses `budget.name` `422 budget_refused`, since
  checking a named Budget needs Lux and an owner token.

While its experiments run:

- a cell's cost check leases no Key: its estimate is zero, since an
  external trial's own spend is not drawn on the experiment's Budget
  and no grader of the profile calls a model, and a zero estimate is
  admitted without a lease (spec 005);
- a submit or an import takes each output only as `{path, arca: {path,
  digest}}`, and Examen records the path and the digest as the trial's
  output evidence and never reads the object: it checks no digest and
  writes no output manifest, and no grader reads an output. An output
  carried as `data`, a `transcript` and a `final_message` are `422
  core_not_configured` with `details.core` `arca`, since there is no
  file store to write them into;
- every trial's cost is `unknown`: its `lux_requests` and its request
  label are recorded and never read, since reading Lux's records needs
  an owner token (spec 005);
- the budget figures are left out of an experiment's answer, as when a
  key source does not answer.

Where this differs from the general text above: an experiment's create
resolves no pin at a core and asks no minter, where Versioned objects
and Creating an experiment resolve every pin as the owner; an
`external` candidate and a task with outputs need no Arca; a cap
without an authorizer's `budget` limit makes no Budget, and a named
Budget is refused rather than read at Lux; a submitted Arca output is
recorded unread, where External trials reads it and checks its digest;
an inline output, a transcript and a final message are refused, where
External trials writes them into the trial's folder; and an external
trial whose request ids Lux would hold still has cost `unknown`.

a console's section follows it.

## Acceptance criteria

- The served `openapi.yaml` describes every route served and no other,
  every route served is in this spec's tables, and every request and
  response of the handlers validates against the document.
- A pin naming another owner's experiment, and an evaluation naming
  another owner's comparison, that the caller may not read are `422
  reference_not_found`, whatever that experiment's state.
- Every route below the base path but `GET /openapi.yaml` answers `401
  missing_token` without a bearer; the whole surface moves under
  `EXAMEN_BASE_PATH`; the probes answer outside it without a token.
- Applying one body twice answers `201` and then `200` with one digest
  and one version; applying changed content answers `201` with a new
  digest and leaves the earlier version readable, unchanged, by
  `name@digest` and by id; applying the earlier content again answers
  `200` and makes it current.
- One version is read by its name while current, by `name@digest`, by
  its digest and by its id, and all four answers are equal.
- A body reference by name alone, a model alias, an image tag, a branch
  or an agent without its version digest is `422 unpinned_reference`
  naming the member; an apply over a limit of spec 002 is `422
  limit_exceeded` naming the constant.
- A suite version that pins two tasks of one name is refused naming
  `tasks`; a `metadata` key beginning `examen.` is refused.
- A create's `comparisons` makes one declared comparison each, the
  automatic pair's own record when it is that pair in its orientation,
  and refuses each malformed entry with the code this spec gives it;
  `GET /experiments/{id}/declared` answers the declared family with
  every entry, before and after the declared comparisons are computed,
  and the test of independence an `independence` member declares;
  a lease without a candidate hands out every external candidate's
  trials, each naming its candidate.
- A list returns at most `MAX_PAGE_SIZE` items, newest first, and
  walking every page while objects are added returns each object at
  most once; a cursor one list issued is `400 invalid_cursor` on
  another; the experiment, trial and comparison lists narrow by
  suite, candidate and state as their tables say.
- The grid answers one row per task in suite order and one entry per
  candidate, and each entry's state, trial counts, summary, verdict and
  reason equal what the cell, trial, measurement and comparison routes
  answer for the same experiment; a cell whose `denominator` is below
  `MIN_TRIALS_FOR_VERDICT` shows `insufficient`; without `comparison`
  each column shows its automatic comparison, and with it the named one.
- An experiment created without `reference` compares every candidate
  but the first with the first, and its grid carries verdicts while it
  runs, from comparisons with `final` false, and after it completes,
  from comparisons with `final` true.
- Every figure a console shows for a grid or a comparison is a member of
  the answer: a test renders both views from the answers alone and
  compares each figure with the analysis's own output for the same
  measurements.
- A comparison answers one suite-level result per metric of the suite,
  and its rows route answers one task-level result per metric and task;
  each carries both summaries with their denominators, the delta, its
  interval, `p` and `q`, the verdict, the reason and the confounds, and
  an `insufficient` result carries no `p` or `q`.
- A trial list carries each trial's current values, and `metric` with
  `value` keeps exactly the trials whose current value matches,
  `value=missing` those without one.
- `trials` changes while every cell is `pending` and is `409
  immutable_field` once one cell has started; `parallelism` and
  `reference` change on a running experiment.
- An experiment create whose task's environment image, program image or
  check image Cella's admission refuses is `422 image_not_admitted`; one
  with a `topos` candidate and a task without an `instruction` is `422
  instruction_required`; a create the minter answers with
  `sign_in_not_kept` is `403 sign_in_not_kept` and stores nothing.
- A lease answers at most the trials the candidate's rollouts may run
  now, smoke trials before main ones, with input links and no
  reference; a lease that lapses returns its trials to pending; a
  renewal extends it by `EXTERNAL_LEASE`; a submit under a lapsed lease
  is `409 lease_expired`, and of a trial the lease does not hold `409
  lease_not_held`; a repeated identical submit answers `200` and
  changes nothing; a self-reported value of a metric a grader produces
  is `400 invalid_field`.
- A cancel moves a running experiment to `canceled` and keeps every
  trial and measurement readable; a repeated cancel answers `200`; a
  cancel of a `complete` experiment is `409 experiment_finished`.
- A delete of a running experiment is `409 experiment_not_finished`, of
  one a baseline names `409 experiment_is_baseline`, and a permitted
  delete answers `204`.
- A retry of a cell parked `blocked` or `over_budget` resumes it, and of
  any other cell is `409 cell_not_parked`; a re-grade appends one
  generation per trial, and one key appends once.
- A stream opened with `Last-Event-ID` replays every later event in
  sequence order, with no gap and no duplicate, when the reconnect
  reaches another replica; it ends with `end` once the experiment is
  `complete` or `canceled`; it closes at its bearer's expiry; and it
  closes with an `error` event after a deny.
- A state change and its event commit together: a test that stops the
  process between any two statements never finds a state the log lacks.
- Completing or canceling an experiment, and parking a cell, journal
  `experiment.completed`, `experiment.canceled` or `cell.parked` in the
  same transaction, and no sink event holds a content field, by canary
  strings.
- The signature verifies with the documented formula for each of two
  secrets, is fresh on every attempt, and fails for a body changed by
  one byte.
- Delivery retries, holds a 401, drops another 4xx at once, drops after
  `DELIVERY_RETRY_WINDOW`, runs on one replica through the lease row,
  and passes through a pooler in transaction mode; a replica that stops
  renewing loses the lease to another within `DELIVERY_LEASE`.
- A pin of a `complete` experiment answers `201`, a repeat `200`, and a
  pin of another experiment `201` with the previous record named in
  `previous` and kept in the history; a pin under a stale `If-Match` is
  `412`; a pin of a running experiment is `409
  experiment_not_complete`.
- An owner a suite is shared with pins a baseline and applies a bar on
  it under its own name; an owner it is not shared with is refused.
- An evaluation answers `201`, and a repeat with the same `metadata` on
  the same comparison answers `200` with the same evaluation; an
  evaluation whose comparison is still being computed answers `201` in
  state `pending` and completes when the comparison does.
- An import of a matching finished session answers `201` with
  `imported: true` and makes its cell at the first import of its tuple;
  one whose record differs is `422 provenance_mismatch` naming each
  differing field; a repeat is `409 already_imported`; an import into a
  full cell is `409 cell_full`; an experiment in mode `import` starts no
  trial at any executor and completes after its intake is closed.
- A submitted annotation appends one generation; a second submission by
  the same annotator is `409 already_annotated`; one with `regrade`
  appends that annotator's next generation and leaves the earlier ones
  unchanged.
- The same `Idempotency-Key` with the same body answers the first
  response and creates one object, across two replicas; with another
  body, or on another route, it is `409 idempotency_key_reused`; a
  repeat while the first request is served is `409 request_in_progress`
  until `IDEMPOTENCY_RESERVATION` lapses; and a keyed request held past
  `REQUEST_DEADLINE` commits nothing and answers `503 unavailable`.
- A body longer than `MAX_REQUEST_BYTES` is `413 request_too_large`,
  and a subject past `API_REQUESTS_PER_MINUTE` is `429 rate_limited`;
  every `429` carries `Retry-After`.
- An experiment created with `budget.cap_usd_micro` runs on a Budget
  the authorizer named or, with the `lux` key source after v0.1 and no
  authorizer budget, one Examen created as the owner; both or neither member is
  `400 invalid_field`; its answer carries the budget's name, cap,
  spend and remainder, and still answers `200` when the key source
  does not.
- An external past trial imports with times in the past and its declared
  `harness_version` and image, and one whose `harness_version` differs from
  its candidate's is `422 provenance_mismatch`.
- A taxonomy append that drops a mapped raw label is `400
  invalid_field`, and one with stale `If-Match` is `412`.
- Every public route answers without a bearer; an unknown key and a
  denied read are byte for byte the same `404 publication_not_found`,
  and no answer or log line carries the key; a withdrawn version answers
  `410 publication_withdrawn` and a paused publication `410
  publication_paused`; a client address past
  `PUBLIC_REQUESTS_PER_MINUTE` is `429 rate_limited` with
  `Retry-After`.
- A create or `PATCH` naming `visibility: public` is `400
  invalid_field`; a listing is answered only after `publication.list`
  allows it; the link token is in no answer to a caller without
  `publication.update`.
- A submission to a benchmark by another owner is `409
  submissions_closed` whatever its `submissions`, of a private report to an unlisted benchmark
  `409 report_not_shared`, and of a report of another suite version
  `422 suite_mismatch`; a repeat answers `200` with the first.
- An acceptance, at submission or by the owner, into a benchmark
  version holding `MAX_BENCHMARK_ENTRIES` accepted entries is `409
  benchmark_full` and changes nothing; the results answer holds exactly
  `publication`, `version`, `primary_metric`, `reference`, `method`,
  `common`, `entries` and `unranked`, and every `vs_reference` verdict
  follows its `h`; the compare route with `a` equal to `b` is
  `400 invalid_field`, with an id that is no accepted entry of the
  version `404 submission_not_found`, and read with `a` and `b`
  swapped negates `delta` and `interval` and keeps `p` and `h`.
- A listing of a benchmark whose `submissions` is not `reviewed` is
  `409 benchmark_not_reviewed`; a second accepted entry of one
  submitter in a listed benchmark's version is `409 owner_has_entry`.
- A `program` candidate whose credential names a core audience or
  Examen's own is `422 credential_audience_reserved` and stores nothing;
  a publication version at `outputs` or `full` without
  `EXAMEN_FILESTORE_DOWNLOAD_ONLY` is `422 file_store_not_download_only`
  before anything is copied.
- A comparison on request, and an automatic comparison after a
  `reference` changed once a cell left `pending`, answer `exploratory`
  true.
- Every error carries a code of the table, that code's fixed
  `message`, and `details.retryable`; every error but `internal`
  carries `details.detail`; `internal` returns no detail.
- A deny of a route about a stored object is byte for byte the `404` of
  an id that names nothing.
- In the v0.1 profile, an experiment of `external` candidates whose
  suite names no `check`, `model_judge` or `agent_judge` grader is
  created, leased, submitted to, imported into and compared with no
  request to any core and no question to a minter, and an authorizer's
  `limits.budget` is recorded with no request to Lux; a `topos` or
  `program` candidate, a grader of one of those kinds, and a task with
  inputs or references are `422 core_not_configured`; an output carried
  as `data`, a transcript and a final message are `422
  core_not_configured` naming `arca`; an `arca` output is recorded with
  its digest and never read; and every trial's cost is `unknown`.
